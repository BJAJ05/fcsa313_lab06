## Хэсэг A: Category-Partition

### A1: Сонголт ба төлөөлөх утгууд

Тестлэх API:
```
POST /transfer { "from": ID, "to": ID, "amount": NUM, "currency": CODE }
```

| Параметр / сонголт | Төлөөлөх утга | Тайлбар                                                                    |
| ------------------ | ------------- | -------------------------------------------------------------------------- |
| From               | Valid         | Хүчинтэй данс                                                              |
|                    | Frozen        | Царцаагдсан данс                                                           |
|                    | Missing       | Байхгүй данс                                                               |
| To                 | Valid         | Шилжүүлэгчээс өөр хүчинтэй данс                                            |
|                    | Missing       | Байхгүй данс                                                               |
|                    | SameAsFrom    | Шилжүүлэгч данстай ижил данс                                               |
| Amount             | Normal        | Үлдэгдэл болон өдрийн лимитээс ихгүй эерэг тоо                             |
|                    | Zero          | Тэг болон түүнээс бага дүн                                                 |
|                    | AtBalance     | Үлдэгдэлтэй яг тэнцүү дүн                                                  |
|                    | OverBalance   | Хөрвүүлсэн дүн үлдэгдлээс хэтэрсэн                                         |
|                    | OverLimit     | Хөрвүүлсэн дүн өдрийн лимитээс хэтэрсэн                                    |
| Currency           | Same          | Хүсэлтийн валют шилжүүлэгч дансны валюттай ижил                            |
|                    | Different     | Хүсэлтийн валют шилжүүлэгч дансны валюттай өөр учир хөрвүүлэх шаардлагатай |

Орчны нөхцөлүүд:
- Дансны идэвхжил: Данс системд оршин буй, идэвхтэй эсвэл царцаагдсан байдлаар урьдчилан тохируулагдсан байх.
- Боломжит үлдэгдэл: Тухайн дансны валютаар илэрхийлэгдэх зарлага гаргах боломжтой мөнгөн дүн.
- Өдрийн гүйлгээний лимит: Тухайн харилцагчийн үлдэж буй өдрийн гүйлгээний дээд хязгаар.
- Валютын ханш: Өөр валют хооронд шилжүүлэг хийх үед ашиглагдах ханшийн мэдээлэл (үндсэн үлдэгдэл болон лимитийн шалгалтыг хөрвүүлсэн дүнгээр тооцно).

### A2: Хязгаарлалтууд

**Алдааны давуу эрэмбэ**:

`ERROR_NO_FROM` > `ERROR_FROZEN` > `ERROR_NO_TO` > `ERROR_SAME_ACCOUNT` > `ERROR_BAD_AMOUNT` > `ERROR_INSUFFICIENT` > `ERROR_LIMIT`

Алдааны эрэмбийг дараах логикоор тогтоосон: эхлээд шилжүүлэгч данс, дараа нь хүлээн авагч данс, хамгийн сүүлд мөнгөн дүн. Учир нь дүнгийн шалгалт нь хоёр данс хүчинтэй байхыг урьдчилсан нөхцөл болгодог.

**Тэмдэглэгээ ба үндэслэл**:

| Утга                 | Тэмдэглэгээ     | Үндэслэл                                                                                           |
| :------------------- | :-------------- | :------------------------------------------------------------------------------------------------- |
| From = Frozen        | `[ERROR]`       | Бусад илүү өндөр тэргүүлэх алдаа байхгүй үед `ERROR_FROZEN` алдааг дангаар илэрхийлнэ.             |
| From = Missing       | `[ERROR]`       | Шилжүүлэгч данс байхгүйг илтгэх `ERROR_NO_FROM` алдааны ангилал.                                   |
| To = Missing         | `[ERROR]`       | Хүлээн авагч данс байхгүйг илтгэх `ERROR_NO_TO` алдааны ангилал.                                   |
| To = SameAsFrom      | `[ERROR]`       | Ижил данс хооронд гүйлгээ хийх үеийн `ERROR_SAME_ACCOUNT` алдаа.                                   |
| Amount = Zero        | `[ERROR]`       | Тэг болон сөрөг дүнг илэрхийлэх `ERROR_BAD_AMOUNT` алдааны ангилал.                                |
| Amount = Normal      | *(Байхгүй)*     | Эерэг дүн бөгөөд хөрвүүлсний дараах дүн нь дансны үлдэгдэл болон өдрийн үлдсэн лимитээс хэтрэхгүй. |
| Amount = AtBalance   | `[SINGLE]`      | Дансны үлдэгдэлтэй яг тэнцүү байх хязгаарын утгыг шалгахад зориулсан туршилт.                      |
| Amount = OverBalance | `[ERROR]`       | Дансны үлдэгдлээс хэтэрсэн үед үүсэх `ERROR_INSUFFICIENT` алдаа.                                   |
| Amount = OverLimit   | `[ERROR]`       | Өдрийн гүйлгээний лимитээс хэтэрсэн үед үүсэх `ERROR_LIMIT` алдаа.                                 |
| Currency = Same      | *(Энгийн утга)* | `currency` утга дансны валюттай ижил тул хөрвүүлэлт хийх шаардлагагүй.                             |
| Currency = Different |                 | `currency` утга дансны валютаас өөр тул ханшаар хөрвүүлэлт хийх шаардлагатай.                      |

**IF Хязгаарлалтууд**:
```
IF [From] = "Missing" THEN [Amount] = "Normal";
IF [To] = "Missing" THEN [Amount] = "Normal";
```

*Тайлбар: Шилжүүлэгч эсвэл хүлээн авагч данс системд байхгүй тохиолдолд дүнг шалгах шаардлагагүйгээр тухайн дансны байхгүй алдааг нэн тэргүүнд буцаах учир илүүдэл хослолуудыг IF хязгаарлалтаар хасна*

**Хослолын тооцоо**:

- Хязгаарлалтгүй бүрэн хослолын тоо (N):
    - Параметрүүд: $\text{From}\ (3) \times \text{To}\ (3) \times \text{Amount}\ (5) \times \text{Currency}\ (2)$
    - Тооцоо: $N = 3 \times 3 \times 5 \times 2 = 90$
- Хязгаарлалтын дараах хослолын тоо (M):
    - Нийт 9 ширхэг (From, To) хослолоос 5 нь байхгүй дансны нөхцөл агуулна: `From = Missing` үед 3 хослол, харин `From` $\neq$ `Missing` ба `To = Missing` үед нэмэлт 2 хослол байна. Эдгээр 5 хослолд IF хязгаарлалтын дагуу зөвхөн `Amount = Normal` сонголт зөвшөөрөгдөнө: $5 \times 1 \times 2 = 10$.
    - Үлдэх 4 хослолд From болон To утгуудын аль нь ч `Missing` биш. Эдгээр хослолд `Amount`-ийн 5 утга, `Currency`-ийн 2 утга чөлөөтэй хэрэгжинэ: $4 \times 5 \times 2 = 40$.
    - Хязгаарлалтын дараах нийт комбинацийн тоо: $M = 10 + 40 = 50$
- Үр дүн (зөвхөн IF хязгаарлалттай): $90 \rightarrow 50$
- `[ERROR]`/`[SINGLE]`-тэй гар аргын Category-Partition тооцоо: `[ERROR]` утга бүр ганц тест өгнө (From: Frozen, Missing; To: Missing, SameAsFrom; Amount: Zero, OverBalance, OverLimit -> 7), `[SINGLE]` `AtBalance` -> 1, бусад бүх утга хүчинтэй үед Currency-ийн 2 утга -> 2. Иймд $90 \rightarrow 7 + 1 + 2 = 10$ (A3-ын 1–10-р спецификаци).

## Хэсэг B

### B1

- **2-way**: Лекц дээр гараар зохиоход 9 мөрөнд багтаж байсан бол PICT хэрэгсэл нь 10 мөр үүсгэсэн. Учир нь PICT greedy алгоритмаар ажилладаг ба хамгийн цөөн мөртэй хамгийн оновчтой covering array-г ямагт олдог баталгаа байхгүй, харин хангалттай сайн дөхдөг.
- **3-way**: Гурван хүчин зүйлийн харилцан үйлчлэлийг шаарддаг тул 2-way-гээс илүү олон тест шаардаж 20 мөр болж нэмэгдсэн. Гэсэн хэдий ч энэ нь бүрэн олонлогийн 144 комбинациас хамаагүй цөөн бөгөөд combinatorial testing-ийн үр ашгийг харуулж байна.

Model файл: [browser.model](browser.model)

### B2: Шилжүүлгийн моделийг PICT-ээр бичих

Happy path мөр гэж `From = Valid`, `To = Valid`, `Amount = Normal` эсвэл `AtBalance` байх мөрийг тооцов. `Currency` нь `Same` эсвэл `Different` байж болно.

Олон алдааны утга агуулсан мөр гэж `From = Frozen` эсвэл `Missing`, `To = Missing` эсвэл `SameAsFrom`, `Amount = Zero`, `OverBalance` эсвэл `OverLimit` гэсэн алдааны сонголтуудаас хоёр буюу түүнээс олон нь нэг мөрөнд зэрэг орсон тохиолдлыг тооцов.

| Хэмжигдэхүүн                        | transfer-nc | transfer | transfer-neg |
| ----------------------------------- | ----------- | -------- | ------------ |
| Үүссэн тест мөрийн тоо              | 15          | 13       | 18           |
| Happy path мөрийн тоо               | 0           | 1        | 4            |
| Олон алдааны утга агуулсан мөр      | 10          | 9        | 0            |
| Нэг мөр дэх хамгийн олон сөрөг утга | 3           | 3        | 1            |

Model файлууд: [transfer-nc.model](transfer-nc.model), [transfer.model](transfer.model), [transfer-neg.model](transfer-neg.model)

#### Шинжилгээ ба дүгнэлт

- **Хязгаарлалтгүй загвар (`transfer-nc`):** 15 тест мөр үүссэн бөгөөд үүнээс 10 мөр олон алдааны сонголт агуулж байна. Тухайлбал, `Missing | Missing | OverBalance | Same` мөрөнд гурван алдааны нөхцөл зэрэг орсон. Энэ нь error masking буюу эхэлж шалгагдсан алдаа бусад алдааг халхлах эрсдэлийг харуулж байна.
- **IF хязгаарлалттай загвар (`transfer`):** Тестийн мөрийн тоо 13 болж буурсан боловч 9 мөр олон алдааны сонголт агуулсан хэвээр байна. Учир нь IF нөхцөлүүд зөвхөн `From = Missing` эсвэл `To = Missing` үед `Amount = Normal` байхыг шаарддаг. Харин `Frozen`, `SameAsFrom`, `Zero` зэрэг бусад алдааны сонголтыг хооронд нь хориглодоггүй. Иймээс IF хязгаарлалт бүх олон алдаатай комбинацийг устгадаггүй.
- **Сөрөг утгатай загвар (`transfer-neg`):** 18 тест мөр үүссэн бөгөөд happy-path 4 мөр, олон алдааны сонголт давхар агуулсан мөр 0 байна. `~` тэмдэглэгээ нь нэг мөрөнд хамгийн ихдээ нэг сөрөг утга оруулах хязгаарлалт тогтоодог. Гэхдээ энэ нь тестийн мөрийн нийт тоог заавал багасгана гэсэн үг биш. PICT шаардлагатай хосуудыг хамруулах ёстой бөгөөд greedy алгоритм хамгийн цөөн мөртэй шийдлийг баталгаажуулдаггүй.
- **Хязгаарлалт шаардлагатай эсэх:** `~` ашиглавал A2-ын хоёр IF хязгаарлалт илүүдэнэ. Тэдгээрийн зорилго нь Missing-тэй олон алдааг нэг мөрөнд оруулахгүй байх байсан бөгөөд `~` үүнийг өөрөө хийнэ. Харин олон алдаатай мөр гарахаа больсон тул давуу эрэмбийг шалгах мөрүүдийг (11, 12-р спецификаци шиг) гараар нэмнэ.



### B3: Бодит тест кейсүүд

PICT-ийн үр дүнгийн файлуудаас бодит мөрүүдийг сонгож, setup (орчны тохиргоо), input (оролтын хүсэлт), oracle (хүлээгдэх үр дүн) бүхий 3 тест кейс боловсруулав.

- **PICT мөр:** Valid | Valid | Normal | Same
- **Setup:** Шилжүүлэгч данс `A` идэвхтэй, царцаагдаагүй; хүлээн авагч данс `B` оршин буй бөгөөд `A`-аас өөр; дансны үлдэгдэл 500, өдрийн үлдсэн лимит 1000; хоёр дансны валют ижил (USD).

#### 2. TC-02: Single Error (Дансны царцаагдсан байдлыг шалгах)

- **Эх сурвалж файл:** `results/transfer-neg.txt`
- **PICT мөр:** ~Frozen | Valid | Normal | Same
- **Setup:** Шилжүүлэгч A данс системд оршин байгаа боловч царцаагдсан (`Frozen`) бөгөөд 500 USD үлдэгдэлтэй. Хүлээн авагч B данс хүчинтэй, A-аас өөр. Өдрийн үлдсэн лимит 1000 USD байна. Хүсэлт дэх валют USD, шилжүүлэх дүн 100 USD тул дансны үлдэгдэл болон лимитийн нөхцөл хангагдсан боловч шилжүүлэгч данс царцаагдсан байна.
- **Input:**
```
POST /transfer

    "from": "A",
    "to": "B",
    "amount": 100,
    "currency": "USD"
}
```

#### 3. TC-03: Currency Conversion + AtBalance (Валют хөрвүүлэлт ба үлдэгдлийн хилийн утга)
- **Эх сурвалж файл:** `results/transfer.txt`
- **PICT мөр:** `Valid | Valid | AtBalance | Different`
- **Setup:** Шилжүүлэгч A данс USD валюттай, идэвхтэй бөгөөд царцаагдаагүй. Хүлээн авагч B данс хүчинтэй, MNT валюттай бөгөөд A-аас өөр. A дансны боломжит үлдэгдэл 10 USD, өдрийн үлдсэн лимит 1000 USD. Ханшийг `1 USD = 3500 MNT` гэж тохируулна. Хүсэлт дэх `35000 MNT` нь хөрвүүлсний дараа `10 USD` болох бөгөөд энэ нь дансны боломжит үлдэгдэлтэй яг тэнцүү, өдрийн үлдсэн лимитээс бага байна.
- **Input:**
```
POST /transfer
{
  "from": "A",
  "to": "B",
  "amount": 35000,
  "currency": "MNT"
}
```
- **Oracle:** `HTTP 201`, `{"result":"OK"}`


### Дүгнэлт

Гараар Category-Partition аргыг ашиглан шилжүүлгийн функцэд сонголт, утга, хязгаарлалт, алдааны давуу эрэмбийг тодорхойлж, 12 спецификацтай хүснэгт гаргасан. `[ERROR]` тэмдэглэгээ нь алдааны ангиудыг тусгаарлаж, `[SINGLE]` нь `AtBalance` хилийн утгыг ганц тестээр шалгахад тусалсан.

PICT-ээр browser загварт 2-way (10 мөр) болон 3-way (20 мөр) covering array үүсгэсэн нь бүрэн олонлогийн 144-өөс хамаагүй цөөн боловч, greedy алгоритмын улмаас лекц дээрх гараар хийсэн 9 мөрөөс нэг мөр илүү гарсан. Transfer загварт IF хязгаарлалт нь мөрийн тоог 15-аас 13 болгон бага зэрэг л цөөлсөн бөгөөд 9 мөр олон алдаатай хэвээр, `Missing | SameAsFrom` шиг утгагүй хослол ч үлдсэн. Сөрөг утгын `~` тэмдэглэгээ нь нэг мөрөнд ганц алдаа оруулж error masking-ээс сэргийлсэн ч мөрийн тоог (18) багасгаагүй. Гараар хийсэн хүснэгт нь алдааны семантик, давуу эрэмбэ, хүлээгдэх үр дүнг (oracle) илүү сайн барьдаг боловч хосын хамралтыг баталгаажуулдаггүй. Харин PICT нь хос бүрийн хамралтыг баталгаажуулдаг боловч oracle өгдөггүй тул хүлээгдэх үр дүнг гараар тодорхойлно. Иймээс хоёр аргыг хослуулах нь зүйтэй: PICT-ээр хослолыг үүсгэж, хязгаарлалт болон давуу эрэмбийг гараар тодорхойлно.

Энэ лабын хамгийн их бодол шаардсан алхам нь алдааны давуу эрэмбийг тогтоож, түүнд нийцсэн PICT хязгаарлалтыг томьёолох байсан.

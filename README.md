## Хэсэг A: Category-Partition

### A1: Сонголт ба төлөөлөх утгууд

Тестлэх API:
```
POST /transfer { "from": ID, "to": ID, "amount": NUM, "currency": CODE }
```

| Параметр / сонголт | Төлөөлөх утга | Тайлбар                                         |
| ------------------ | ------------- | ----------------------------------------------- |
| From               | Valid         | Хүчинтэй данс                                   |
|                    | Frozen        | Царцаагдсан данс                                |
|                    | Missing       | Байхгүй данс                                    |
| To                 | Valid         | Шилжүүлэгчээс өөр хүчинтэй данс                 |
|                    | Missing       | Байхгүй данс                                    |
|                    | SameAsFrom    | Шилжүүлэгч данстай ижил данс                    |
| Amount             | Normal        | Үлдэгдэл болон өдрийн лимитээс ихгүй эерэг тоо  |
|                    | Zero          | Тэг болон түүнээс бага дүн                      |
|                    | AtBalance     | Үлдэгдэлтэй яг тэнцүү дүн                       |
|                    | OverBalance   | Хөрвүүлсэн дүн үлдэгдлээс хэтэрсэн              |
|                    | OverLimit     | Хөрвүүлсэн дүн өдрийн лимитээс хэтэрсэн         |
| Currency           | Same          | Шилжүүлэгч болон хүлээн авагч дансны валют ижил |
|                    | Different     | Валют хөрвүүлэх шаардлагатай                    |

Орчны нөхцөлүүд:
- Дансны идэвхжил: Данс системд оршин буй, идэвхтэй эсвэл царцаагдсан байдлаар урьдчилан тохируулагдсан байх.
- Боломжит үлдэгдэл: Тухайн дансны валютаар илэрхийлэгдэх зарлага гаргах боломжтой мөнгөн дүн.
- Өдрийн гүйлгээний лимит: Тухайн харилцагчийн үлдэж буй өдрийн гүйлгээний дээд хязгаар.
- Валютын ханш: Өөр валют хооронд шилжүүлэг хийх үед ашиглагдах ханшийн мэдээлэл (үндсэн үлдэгдэл болон лимитийн шалгалтыг хөрвүүлсэн дүнгээр тооцно).

### A2: Хязгаарлалтууд

**Алдааны тэргүүлэх дараалал**:

`ERROR_NO_FROM` > `ERROR_FROZEN` > `ERROR_NO_TO` > `ERROR_SAME_ACCOUNT` > `ERROR_BAD_AMOUNT` > `ERROR_INSUFFICIENT` > `ERROR_LIMIT`

**Тэмдэглэгээ ба үндэслэл**:

| Утга                 | Тэмдэглэгээ                  | Үндэслэл                                                                                           |
| :------------------- | :--------------------------- | :------------------------------------------------------------------------------------------------- |
| From = Frozen        | `[ERROR]`                    | Бусад илүү өндөр тэргүүлэх алдаа байхгүй үед `ERROR_FROZEN` алдааг дангаар илэрхийлнэ.             |
| From = Missing       | `[ERROR]`                    | Шилжүүлэгч данс байхгүйг илтгэх `ERROR_NO_FROM` алдааны ангилал.                                   |
| To = Missing         | `[ERROR]`                    | Хүлээн авагч данс байхгүйг илтгэх `ERROR_NO_TO` алдааны ангилал.                                   |
| To = SameAsFrom      | `[ERROR]`                    | Ижил данс хооронд гүйлгээ хийх үеийн `ERROR_SAME_ACCOUNT` алдаа.                                   |
| Amount = Zero        | `[ERROR]`                    | Тэг болон сөрөг дүнг илэрхийлэх `ERROR_BAD_AMOUNT` алдааны ангилал.                                |
| Amount = Normal      | *(Байхгүй)*                  | Эерэг дүн бөгөөд хөрвүүлсний дараах дүн нь дансны үлдэгдэл болон өдрийн үлдсэн лимитээс хэтрэхгүй. |
| Amount = AtBalance   | `[SINGLE]`                   | Дансны үлдэгдэлтэй яг тэнцүү байх хязгаарын утгыг шалгахад зориулсан туршилт.                      |
| Amount = OverBalance | `[ERROR]`                    | Дансны үлдэгдлээс хэтэрсэн үед үүсэх `ERROR_INSUFFICIENT` алдаа.                                   |
| Amount = OverLimit   | `[ERROR]`                    | Өдрийн гүйлгээний лимитээс хэтэрсэн үед үүсэх `ERROR_LIMIT` алдаа.                                 |
| Currency = Same      | *(Энгийн утга)*              | `currency` утга дансны валюттай ижил тул хөрвүүлэлт хийх шаардлагагүй.                             |
| Currency = Different | `[PROPERTY convertCurrency]` | `currency` утга дансны валютаас өөр тул ханшаар хөрвүүлэлт хийх шаардлагатай.                      |

**IF Хязгаарлалтууд**:
```
IF [From] = "Missing" THEN [Amount] = "Normal";
IF [To] = "Missing" THEN [Amount] = "Normal";
```

*Тайлбар: Шилжүүлэгч эсвэл хүлээн авагч данс системд байхгүй тохиолдолд дүнг шалгах шаардлагагүйгээр тухайн дансны байхгүй алдааг нэн тэргүүнд буцаах учир илүүдэл хослолуудыг IF хязгаарлалтаар хасна*

**Хослолын тооцоо**:

- Хязгаарлалтгүй бүрэн хослолын тоо (N):
    - Параметрүүд: $\text{From}\ (3) \times \text{To}\ (3) \times \text{Amount}\ (5) \times \text{Currency}\ (2)$
    - Тооцоо: $N = 3 \times 3 \times 5 \times 2 = 90$
- Хязгаарлалтын дараах хослолын тоо (M):
    - Нийт 9 ширхэг (From, To) хослолоос 5 нь байхгүй дансны нөхцөл агуулна: `From = Missing` үед 3 хослол, харин `From` $\neq$ `Missing` ба `To = Missing` үед нэмэлт 2 хослол байна. Эдгээр 5 хослолд IF хязгаарлалтын дагуу зөвхөн `Amount = Normal` сонголт зөвшөөрөгдөнө: $5 \times 1 \times 2 = 10$.
    - Үлдэх 4 хослолд From болон To утгуудын аль нь ч `Missing` биш. Эдгээр хослолд `Amount`-ийн 5 утга, `Currency`-ийн 2 утга чөлөөтэй хэрэгжинэ: $4 \times 5 \times 2 = 40$.
    - Хязгаарлалтын дараах нийт комбинацийн тоо: $10 + 40 = 50$
- Үр дүн: $90 \rightarrow 50$

## Хэсэг B

### B1

- **2-way**: Лекц дээр гараар зохиоход 9 мөрөнд багтаж байсан бол PICT хэрэгсэл нь 10 мөр үүсгэсэн. Учир нь PICT greedy алгоритмаар ажилладаг ба хамгийн цөөн мөртэй хамгийн оновчтой covering array-г ямагт олдог баталгаа байхгүй, харин хангалттай сайн дөхдөг.
- **3-way**: Гурван хүчин зүйлийн харилцан үйлчлэлийг шаарддаг тул 2-way-гээс илүү олон тест шаардаж 20 мөр болж нэмэгдсэн. Гэсэн хэдий ч энэ нь бүрэн олонлогийн 144 комбинациас хамаагүй цөөн бөгөөд combinatorial testing-ийн үр ашгийг харуулж байна.


### B2

Шилжүүлгийн функцэд зориулж 3 өөр хэлбэрээр PICT загвар зохиож үр дүнг харьцуулав:
1. `transfer-nc.model`: Ямар нэгэн хязгаарлалтгүй.
2. `transfer.model`: `IF [From] = "Missing" THEN [Amount] = "Normal";` болон `IF [To] = "Missing" THEN [Amount] = "Normal";` хязгаарлалттай.
3. `transfer-neg.model`: Алдааны утгуудыг `~` тэмдэглэгээгээр тэмдэглэсэн сөрөг утгат загвар.

#### Харьцуулалтын хүснэгт

| Хэмжигдэхүүн                            | transfer-nc | transfer            | transfer-neg                       |
| :-------------------------------------- | :---------- | :------------------ | :--------------------------------- |
| **Үүссэн тест мөрийн тоо**              | 15          | 13                  | 18                                 |
| **Happy-path мөрийн тоо**               | Гарсан      | Гарсан              | Гарсан                             |
| **Олон алдаа зэрэг агуулсан мөр**       | Байгаа      | Байхгүй (IF хассан) | Байхгүй (~ дүрмээр хязгаарлагдсан) |
| **Нэг мөр дэх хамгийн олон сөрөг утга** | Хязгааргүй  | Хязгааргүй          | Ихдээ 1                            |

#### Шинжилгээ ба дүгнэлт:
- **Хязгаарлалтгүй загвар (`transfer-nc`):** Систем байхгүй данс болон бусад алдаануудыг дур мэдэн хольж нэг мөрөнд олон алдаа зэрэг үүсгэх тул error masking (эхний алдаа бусдыгаа халхлах) үзэгдэл гарна.
- **IF хязгаарлалттай загвар (`transfer`):** Логик бус болон шаардлагагүй давхардсан хослолуудыг (тухайлбал байхгүй данс дээр дүнг шалгах алдааг) шүүж цөөрүүлдэг.
- **Сөрөг утгатай загвар (`transfer-neg`):** PICT-ийн `~` тэмдэглэгээ нь нэг тест мөрөнд хамгийн ихдээ нэг л сөрөг утга орохыг баталгаажуулдаг. Гэхдээ энэ нь бизнес логикийн тусгай `IF` нөхцөлийг (жишээ нь байхгүй дансны үед अमाउंट хэвийн байх) автоматаар бүрэн орлож чадахгүй тул семантик хязгаарлалттай хослуулан хэрэглэх нь илүү оновчтой.
